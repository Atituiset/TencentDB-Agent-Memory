TencentDB Agent Memory 深度指南

mem: 会话指令

mem: 指令是 Proxy 提供的最轻量的记忆操作入口：在对话里直接输入 mem: 开头的指令，Proxy 会拦截并就地处理——不用离开当前会话去开面板，也不用记 API。

现有指令

随 v2.0.0 发布，当前共三个：

指令说明
mem:sync刷新本次会话的全部资产注入（Skill / 记忆 / Knowledge / Task & Agent 描述）
mem:create-skill [提示词]把本次对话归档为 Skill，后台异步提取
mem:help显示指令帮助

格式约定：mem:<command>，冒号后不加空格，命令名大小写不敏感。

典型使用场景

mem:sync —— 你刚在面板上给当前 Agent 新绑了一个 Wiki 或改了 system prompt，但会话已经开了很久。输入 mem:sync，Proxy 重新拉取全部资产并刷新注入内容，无需重开会话。

mem:create-skill —— 刚和 agent 一起搞定了一次复杂的线上排障。输入 mem:create-skill，对话被归档进 Skill 抽取缓冲区，后台 LLM 异步提炼出带版本、步骤和验证规则的候选 Skill；稍后在面板审核发布。可选提示词可以引导抽取重点。

mem:help —— 除了查看用法，它还有一个隐藏价值：验证注入链路是否正常。如果 mem:help 没有响应，说明请求根本没经过 Proxy 的指令拦截层——通常是 base URL 配错或 session 未初始化。

实现机制

拦截发生在 Proxy 的请求预处理阶段（源码 src/mem-command/）：检测到用户消息以 mem: 开头时，Proxy 不把该消息转发给上游 LLM，而是就地生成响应返回。这意味着：

  • 指令消耗零 token；
  • 响应速度与上游模型无关；
  • 对客户端完全透明——任何走 Proxy 的客户端都能用，无论 CC、CodeBuddy 还是 Codex。

session init 完成是使用指令的前提：未绑定 team/agent/task 的会话中，涉及资产的指令没有作用对象。

路线图上的扩展

v2.0.1 计划把指令能力扩展到 Task 维度：

  • 在对话里直接创建 Task、更新 Task；
  • Task 与记忆资产的关联在会话内即时生效。

动机很实际："Task 是记忆归属的组织方式。能在对话里就地维护它，才不会出现『事情做完了，Task 还停在三天前的描述』。"

官方同时明确表示：接下来做哪些指令取决于真实使用中的需求——你在实际场景里反复需要什么操作（查看当前注入了什么？临时禁用某个资产？把某段对话存成记忆？），欢迎到 Issues 描述使用场景（比接口设计更有价值）。
